### Единственный измеренный ориентир (M10)

`out/probe_lm_budget.json`, RTX 4080 SUPER 16 ГБ, синтетическая модель 0.517B,
bf16: **14 842 токена/с** при контексте 1024, микробатче 1, накоплении 8.
Экстраполяция при duty 0.70: 10B токенов ≈ 11 дней, 100B ≈ 111 дней.

Это **нижняя граница** (4.62 ГиБ / 16, checkpointing вкл.). Для D1 ~300M нужен
**новый** throughput probe (4080 → 1×/2× 6000 Pro) до обещания календаря.

## Что определяет стоимость сильнее всего

**Frame rate кодека.** 12 Hz vs 7.5 Hz удлиняет speech sequence относительно
VibeVoice-тракта — закладывать в VRAM и tokens/s (`ОЦЕНКА` до probe).

**Длина text prefix + speech.** D1 использует полный text prefix (не dual-track
streaming) до прохождения content gates — упрощает align, увеличивает
последовательность на коротких репликах умеренно.

**Число codebooks / MTP.** 16 codebooks: CE weights и MTP compute; CB0-AR —
критический путь латентности на инференсе.

**Размер модели.** ~300M vs 10B MoE — порядок разницы.

**Данные.** D1 ограничен ~73 ч + CPT; 500+ ч — только D2 после GO (стоимость
хранения/encode растёт линейно).

## Требования по латентности

Целевой сценарий телефонии остаётся, но **D1 ставит content gates раньше TTFB**.

| Метрика | Цель | Гейт |
|---------|------|------|
| TTFB, тёплый старт | ≤ 300 мс | N8 (после N3) |
| RTF | ≤ 0.3 | N8 |
| Холодный старт | измеряется отдельно | — |

Разложение TTFB: фронтенд, LM prefill, первый CB0, MTP, первый чанк decode
кодека. Скрипт-ориентир Track A: `scripts/18_measure_ttfb.py` — адаптировать
под discrete path.

Определение TTFB: от завершения нормализации текста до первого PCM буфера
≥ 20–40 мс.

## Инфраструктурные требования к коду

- **DDP** в discrete LM trainer (1–2 GPU).
- **Resume** optimizer/scheduler/RNG.
- **bf16** + grad accumulation.
- **Стриминговые shards** codec tokens.
- **`run_manifest.json`**: git_sha, codec hash, param counts, trainable lists.
- **Гигиена артефактов:** не коммитить веса, аудио, HF caches.
- WSL: не train с `/mnt/c/...`; перед GPU — `git pull` + SHA.

## Правила окружения

Сохраняются из текущего проекта:

- GPU-работа в WSL, не native Windows Python.
- Артефакты в Linux FS; числа/отчёты — в `.cursor/results/` и `docs/`.
- Длинные задачи — `tmux` + tee в лог прогона.
- Wavs зеркалировать на Windows `out/<plan_slug>/` для listen.

# Методология MiniSpeech-RU — Track N

Рабочий свод по переходу от Track A (mel, from-scratch, ~10M) к **Track N** —
собственной реализации архитектуры *next-token diffusion* для русского языка.

Статус: **проектирование**. Ни один компонент Track N ещё не реализован.
Track A остаётся текущим production и переходит в статус baseline.

## Что такое Track N

Концепция (не веса) из линии LatentLM → VibeVoice: непрерывные речевые
токенизаторы на сверхнизкой частоте кадров + предобученный LLM как контекстный
предиктор + лёгкая diffusion-голова для акустических деталей.

Мы **не** дообучаем чужие веса. Мы воспроизводим и улучшаем архитектурную идею
на собственных токенизаторах, собственной diffusion-голове и русскоязычном
бэкбоне.

## TL;DR стратегии

| Вопрос | Ответ |
|--------|-------|
| Зачем | Открытого качественного русского TTS нет; VibeVoice-класс не знает русского |
| Что строим | Семейство: **N-Lite** (~0.5B, телефония, суверенный путь) и **N-Pro** (GigaChat-бэкбон, национальный путь) |
| Чужие веса | Только как референс и верхняя граница, не в продукте |
| Научный тезис | Intelligibility-critical TTS: метрика — семантическая точность, а не MOS |
| Что переносим из Track A | Фронтенд, бенчмарк, гейты, ASR-обвязка, культура измерений |
| Что становится baseline | mel-модель `runs/mel_stress_v01_s4` |

## Правила работы с этими документами

1. **Разделяем измеренное и предполагаемое.** Числа из наших прогонов помечены
   ссылкой на артефакт (`out/*.json`, `docs/*.md`). Внешние числа — ссылкой на
   источник. Оценки помечены `ОЦЕНКА`.
2. **Не переписываем историю.** Track A и Part 1 — не ошибка, а измерение,
   которое определило Track N. См. [01_strategy.md](01_strategy.md).
3. **Ни один архитектурный выбор без гейта.** Каждая фаза в
   [09_roadmap.md](09_roadmap.md) имеет критерий перехода.
4. Обновляем при получении новых измерений; помечаем дату в разделе.

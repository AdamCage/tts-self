# 07 — Данные

Данные, а не GPU, — главное ограничение Track N. Раздел определяет, что нужно,
где брать и в каком порядке.

> **Все объёмы и лицензии в этом файле помечены как требующие проверки.**
> Ничего не закладывать в план до фактической проверки доступности и условий
> использования. Причина отдельная и серьёзная: с 01.03.2027 действуют правила
> использования результатов интеллектуальной деятельности при обучении
> суверенных и национальных моделей — см. [02_legal.md](02_legal.md).

## Три разных потребности

Их часто путают, а требования различаются радикально.

| Потребность | Что нужно | Разметка | Качество | Объём |
|-------------|-----------|----------|----------|-------|
| Акустический токенизатор | разнообразное аудио | **не нужна** | важнее разнообразие каналов, чем чистота | тысячи часов |
| Семантический токенизатор | аудио + транскрипт | нужна, псевдо допустима | средняя | сотни–тысячи часов |
| Вторая стадия (LLM + голова) | аудио + транскрипт | нужна, псевдо допустима | средняя, но чистые сегменты предпочтительны | тысячи часов |
| Бэкбон N-Lite | **текст** | — | чистый русский текст | десятки миллиардов токенов `ОЦЕНКА` |

Ключевое облегчение: самый дорогой по вычислениям компонент (акустический
токенизатор) требует **неразмеченного** аудио, которого на русском много.

## Текущее состояние

| Корпус | Часы | Дикторы | Роль |
|--------|-----:|--------:|------|
| RUSLAN (у нас) | ~15.4 clean из ~31 | 1 | Track A production; для Track N — только валидация и абляции |

Это и есть узкое место. Один диктор ограничивает натуральность при **любой**
архитектуре. Многодикторные данные нужны с фазы P1.

## Кандидаты в корпуса

`ПРОВЕРИТЬ` — объёмы указаны по памяти и подлежат подтверждению перед
включением в план. Лицензии проверять индивидуально, включая допустимость
обучения коммерческих моделей.

### Речь: русский, размеченный

| Корпус | Порядок объёма | Профиль | Замечания |
|--------|---------------:|---------|-----------|
| Golos (SberDevices) | ~1200 ч | краудсорс + фарфилд, ASR | Российское происхождение — плюс для правового контура |
| Common Voice ru | сотни часов | краудсорс, разнообразные дикторы | Лицензия CC0 (проверить актуальность) |
| OpenSTT / Russian Open STT | тысячи часов | очень шумный, разнородный | Пригоден для токенизатора, для второй стадии — после фильтрации |
| SOVA Dataset | сотни часов | смешанный | Проверить состав и лицензию |
| M-AILABS ru | десятки часов | TTS-качество | Малый объём, но чистый |

### Речь: русский, неразмеченный

Для акустического токенизатора. Источники: подкасты, аудиокниги, публичные
выступления, YODAS-подобные наборы с YouTube.

Требования те же: реестр происхождения и допустимости использования с первого
дня. Отдельно проверять, не попадает ли материал под ограничения по РИД.

### Речь: телефонный домен

**Критично для N-Lite и, вероятно, отсутствует в открытом доступе.**

Токенизатор, не видевший 8 кГц с телефонными кодеками, будет плохо работать в
целевом канале. Варианты:

1. Собственные данные из банковского доступа (предпочтительно, доступ есть).
2. Симуляция: понижение частоты и прогон широкополосного аудио через
   телефонные кодеки (G.711, G.729, Opus в узкой полосе). Дёшево, но домен
   получается синтетическим.
3. Публичные корпуса телефонных разговоров на русском — искать, вероятно мало.

Практически: комбинировать 1 и 2. Симуляция даёт объём, реальные данные —
калибровку.

### Текст для бэкбона N-Lite

Нужен большой корпус чистого русского текста. `ПРОВЕРИТЬ` доступность и
правовой статус: Википедия, открытые книжные коллекции, новостные архивы,
веб-корпуса с фильтрацией.

Отдельное требование, специфичное для нас: часть корпуса должна иметь
**корректно расставленные ударения**, иначе бэкбон не научится разрешать
омографы (вариант 4 в [06_frontend.md](06_frontend.md)). Источники: словари
ударений, автоматическая расстановка с последующей верификацией, специально
размеченные подкорпуса.

### Банковский домен

Доступ подтверждён. Что именно требуется:

| Тип | Назначение | Приоритет |
|-----|-----------|-----------|
| Тексты сценариев IVR и уведомлений | Домен-специфичный TN, расширение бенчмарка | высокий |
| Логи диалогов | Реальное распределение критических спанов | высокий |
| Записи телефонного канала | Токенизатор под целевой канал | высокий |
| Записи целевого диктора | Голос продукта | средний |

Обязательно: обезличивание до попадания в обучающие данные, и юридическое
оформление допустимости обучения на этих данных.

## Псевдоразметка

Оригинал VibeVoice для обучения на подкастах разработал пайплайн, генерирующий
псевдотранскрипции и метки смены говорящего. Нам нужно то же самое, и **у нас
уже есть большая часть инструментов**.

| Шаг | Существующий инструмент |
|-----|------------------------|
| ASR-транскрипция | `configs/asr.yaml`, обвязка Whisper / GigaAM-CTC |
| Оценка качества транскрипта | `scripts/03_verify_text_asr.py`, `03b_apply_qc.py` |
| Пересмотр по вербализованным ссылкам | `scripts/25_qc_revision.py` |
| Выравнивание | `scripts/26_build_forced_align.py`, MFA |
| Нарезка и манифест | `scripts/02_build_manifest.py` |

Пороги QC уже определены в `docs/experiment_protocol.md`: `clean` при CER ≤ 0.15,
`review` в диапазоне 0.15–0.25, `exclude` выше 0.25. Для токенизатора пороги
можно ослабить — ему транскрипт не нужен вовсе; для второй стадии сохранить.

Полезное наблюдение из Part 1 (E6): пересчёт по вербализованным ссылкам не
вернул ни одного часа из `exclude`, но полноценное переразмечивание CTC-моделью
может вернуть часы, потерянные из-за вставок Whisper. При масштабировании это
стоит проверить — на тысячах часов разница существенна.

## Инфраструктура данных

Текущий слой данных содержит односкорпусные и однодикторные допущения. До
перехода к тысячам часов требуется:

- **Многокорпусный манифест.** Единая схема с полями корпуса, диктора, канала,
  лицензии, качества.
- **Шардирование и стриминг.** Загрузка не должна требовать помещения корпуса в
  память или на локальный SSD целиком.
- **Дедупликация.** На тысячах часов из открытых источников пересечения
  неизбежны, а утечка между train и test обесценит все измерения.
- **Реестр происхождения.** Источник, лицензия, дата, допустимость обучения,
  хеш. Нужен и для науки (воспроизводимость), и для закона.
- **Замороженные тестовые наборы с хешами.** Механизм уже есть
  (`test_set_sha256`), распространить на новые корпуса.

Разделение train и test — **по контейнерам, а не по случайным сегментам**.
Правило уже зафиксировано в проекте: контекстные диапазоны, не случайные
высказывания. При многодикторности добавляется разделение по дикторам для
проверки обобщения.
